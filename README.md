# WORDLINK

친구와 실시간으로 즐기는 한국어 끝말잇기 웹게임입니다. 브라우저에서 바로 실행되고, 방 코드나 초대 링크로 친구를 부를 수 있어요.

> 현재 버전: **v0.4.x** · Node.js 22 이상 · Socket.IO 4.x

## 주요 기능

### 게임
- 2~8인 실시간 대전, 방장 권한과 준비 상태
- 1~25라운드, 라운드가 갈수록 줄어드는 턴 시간, 미션 글자 보너스
- 서버 측 사전 검증 · 끝 글자 연결(두음법칙) · 중복 단어 차단
- 한방 단어 허용/금지 설정
- 가로 단어 체인 표시, 단어 입력 카드(시작 글자 칩, 실시간 규칙 안내)
- 라운드·경기 결과 요약(순위, 단어 수, 가장 긴 단어, 가장 빠른 입력, 플레이 시간)

### 소셜
- 로비: 접속자 목록 · 열린 방 목록 · 로비 채팅 · 빠른 입장
- 방 안 채팅(탈락 후에도 가능, 방마다 최근 60개 보관)
- 이모지 반응 (👍 😂 😮 🔥 👏 😭)
- 방장 추방 (대기실에서만)
- 프로필 사진 선택, 닉네임별 고정 아바타 색
- 소셜 로그인(Google · GitHub · Discord), 마이페이지 · 레벨 · 랭킹

### 편의
- PC · 모바일 반응형, 재접속 시 이전 방 복원
- 효과음 on/off(WebAudio 합성). 남은 시간이 줄수록 긴박한 비트, 내 차례는 마지막 10초에 경고음, 모바일은 마지막 3초에 진동
- 도우미 마스코트 **복구**가 상황별로 말을 걸고 규칙을 설명해 줘요

## 빠른 시작

```bash
npm install
npm start
```

브라우저에서 `http://localhost:3000`에 접속해 방을 만들고, 방 코드나 초대 링크를 친구에게 보내세요. Windows에서는 `start.bat`을 더블클릭해도 됩니다. (첫 실행 때 패키지를 자동 설치해요.)

| 명령 | 설명 |
| --- | --- |
| `npm start` | 서버 실행 |
| `npm run dev` | 파일이 바뀌면 자동 재시작 |
| `npm test` | 테스트 실행 |
| `npm run check` | 구문 검사 |

> `node --test`를 인자 없이 실행하면 `WORDLINK-Render-Fix/` 안의 옛 테스트까지 실행돼요. 항상 `npm test`를 사용하세요.

## 배포하기

`localhost`는 내 컴퓨터에서만 열려요. 친구가 다른 곳에서 접속하려면 인터넷에서 접근 가능한 Node.js 호스팅(Render, Railway, Fly.io, VPS 등)이 필요해요. 정적 호스팅은 안 되고, 서버가 계속 실행되며 WebSocket(Socket.IO)을 지원해야 해요.

| 항목 | 값 |
| --- | --- |
| Build command | `npm install` |
| Start command | `npm start` |
| Runtime | Node.js 22 이상 (26 LTS 권장) |
| 서비스 유형 | 장시간 실행되는 웹 서비스 |

`render.yaml`이 포함돼 있어서 Render에서 저장소를 Blueprint로 연결하면 기본 설정을 불러와요.

> 무료 호스팅은 절전, 접속 제한, 재시작 시 방 초기화가 있을 수 있어요. 특히 **Render 무료 플랜은 재시작 때 디스크가 초기화**되어 저장된 기록도 사라져요. ([기록 저장소](#기록-저장소-중요) 참고)

### 같은 Wi-Fi의 친구와 플레이

1. 서버를 실행한 PC에서 `ipconfig`를 실행해 `IPv4 주소`를 확인합니다. (예: `192.168.0.15`)
2. 친구는 같은 Wi-Fi에서 `http://192.168.0.15:3000`으로 접속합니다.
3. Windows 방화벽에서 Node.js의 개인 네트워크 통신을 허용해야 할 수 있어요.

## 게임 규칙

### 기본
- 2~12글자의 한글 단어만 입력할 수 있어요.
- 첫 글자가 이전 단어의 마지막 글자와 같아야 해요.
- **두음법칙**을 적용해요. 이전 단어가 `리`로 끝나면 `리`/`이`, `라`로 끝나면 `라`/`나`, `녀`로 끝나면 `녀`/`여`로 시작할 수 있어요. (ㄹ·ㄴ + ㅑ ㅕ ㅛ ㅠ ㅣ → ㅇ, ㄹ + ㅏ ㅐ ㅗ ㅚ ㅜ ㅡ → ㄴ, 받침은 유지)
- 같은 게임에서 한 번 쓴 단어는 다시 쓸 수 없어요.
- `words.json`에 있는 단어만 인정해요.
- 제한 시간 안에 입력하지 못하면 **그 라운드에서** 탈락해요. (다음 라운드에는 다시 참가)

### 라운드
- 한 경기는 방장이 정한 1~25라운드로 진행돼요.
- **라운드 총 시간**은 20 / 40 / 60 / 80 / 100 / 150 / 500초 중에서 골라요. 시간이 끝나면 생존자 중 라운드 점수가 가장 높은 사람이 이겨요. (동점이면 무승부) 그 전에 한 명만 남으면 그 사람이 이겨요.
- **턴 제한 시간**은 10 / 15 / 20 / 30초 중에서 고르고, 라운드마다 약 13%씩 줄어 기본 시간의 35%(최소 5초)까지 줄어요.
  - 15초 → 15, 13, 11, 9, 7, 5, 5초
  - 30초 → 30, 26, 22, 18, 15, 12, 11, 11초
- 라운드 사이에는 6초 휴식이 있고, 단어 사슬·미션 글자·시작 순서가 새로 바뀌어요.
- 가장 많은 라운드를 이긴 사람이 최종 우승, 승수가 같으면 총점이 높은 사람이 우승해요.

### 점수 계산

```
점수 = 반올림[ (미션 수 + 2) × (7 × 단어 길이 + 5)^0.74 + 0.88 × 체인 × (남은 시간 비율 + 1) ]
```

| 항목 | 설명 |
| --- | --- |
| 미션 수 | 단어 안에 미션 글자가 들어간 횟수 (없으면 0) |
| 단어 길이 | 단어의 글자 수 |
| 체인 | 이번 라운드에서 지금까지 나온 단어 수 (이번 단어 포함) |
| 남은 시간 비율 | 이번 턴 제한 시간 중 남은 비율 (0~1) |

구현은 `game-rules.js`의 `calcScore()`에 있어요.

### 미션 글자
- 라운드마다 미션 글자가 하나 정해지고 화면 왼쪽 `MISSION` 칸에 표시돼요.
- 미션 글자가 들어간 단어(위치 상관없음)를 내면 점수가 올라요. 단어 기록에는 `🎯×N`으로 표시돼요.
- 사전에서 너무 흔하거나 너무 드문 글자는 후보에서 제외돼요.
- 미션 글자가 사용되면 같은 라운드 안에서도 **즉시 새 미션 글자로 바뀌어요.** (방금 쓴 글자는 제외, 모든 플레이어에게 알림)

### 한방 단어

**한방 단어**는 사전에 이어 갈 단어가 하나도 없는 단어예요. (끝 글자와 두음법칙 변형으로 시작하는 다른 단어가 없음. 예: 가돌리늄)

- 방을 만들 때, 또는 대기실에서 방장이 **`한방 단어 허용` 체크박스**로 정해요. 기본값은 체크(허용)예요.
- 체크를 끄면 한방 단어는 서버에서 거부되고(`ONESHOT`), 턴과 제한 시간은 그대로 유지돼요.
- 방장이 아닌 사람에게는 `허용` / `금지` 글자로 보여요. 금지된 방은 로비 목록에 `한방 금지`로 표시돼요.
- 판정은 사전 기준이고, 서버 시작 시 첫 글자별 단어 수를 미리 계산해요. (`game-rules.js`의 `buildStartIndex()` · `isOneShotWord()`)

## 로비와 방

닉네임을 입력하고 **로비 입장**을 누르면 로비로 들어가요. 방 코드를 몰라도 열린 방을 눌러 바로 참가할 수 있어요.

| 기능 | 설명 |
| --- | --- |
| 접속자 목록 | 접속 중인 사람과 위치(로비 / 대기실 N번 / 게임중 N번). 최대 200명 표시 |
| 방 목록 | 방 번호 · 제목 · 규칙 · 방장 · 인원 · 상태 · 잠금 여부. `입장 가능한 방만` 필터 제공 |
| 방 만들기 | 제목, 비밀번호(선택, 영문·숫자 1~8자), 최대 인원, 라운드 수, 라운드 총 시간, 턴 제한 시간, 한방 단어 허용 |
| 비밀번호 방 | 🔒 방은 비밀번호가 필요해요. 5번 틀리면 30초간 막혀요. 원래 구성원(재접속)은 비밀번호 없이 복귀 |
| 빠른 입장 | 잠기지 않았고 자리가 있는 대기 중인 방 중 사람이 가장 많은 방으로 입장 |
| 코드 입장 / 초대 링크 | 방 코드와 `?room=코드` 링크 지원. 링크로 들어오면 닉네임 입력 후 해당 방으로 이동 |
| 로비 채팅 | 120자 제한, 0.8초 연타 제한, 최근 60개 보관. 방 안에서는 보이지 않음 |
| 방 안 채팅 | 대기실·게임 중 모두 가능, 방마다 최근 60개 보관 |
| 방장 추방 | 대기실에서 `추방` 버튼. 추방된 사람은 그 방에 다시 들어올 수 없음(`KICKED`). 게임 시작 후에는 불가 |

**참고**
- 방장은 대기실에서 방 제목, 비밀번호, 인원, 시간, 라운드 수, 한방 단어 설정을 바꿀 수 있어요.
- 게임이 시작된 방이나 가득 찬 방에는 새로 들어갈 수 없어요.
- 목록에서 종료된 방과 접속자가 없는 방은 숨겨지고, 모두 끊긴 방은 10분 뒤 정리돼요.
- 닉네임은 접속 중인 다른 사람과 겹칠 수 없어요. (같은 사람이 다른 탭·기기에서 다시 들어오는 것은 허용)
- 좁은 모바일 화면에서는 접속자·내 정보 패널을 숨기고 방 목록과 채팅만 보여 줘요.

## 프로필 사진

- 홈 화면의 `프로필 사진 고르기`, 로비 `내 정보`의 `프로필 사진 바꾸기`에서 24개의 이모지 중 하나를 골라요. 고르지 않으면 닉네임 첫 글자가 나와요.
- 방 인원 · 점수판 · 단어 기록 · 로비 접속자 · 랭킹에 표시돼요.
- 로그인한 계정은 서버에 저장되고, 게스트는 브라우저에만 기억돼요.
- 직접 업로드는 지원하지 않고, 서버가 정한 목록(`server.js`의 `AVATARS`)에서만 고를 수 있어요. 목록 밖의 값은 서버가 무시해요.

## 소셜 로그인

홈 화면에서 게스트로 바로 입장하거나, Google · GitHub · Discord 계정으로 로그인해 입장할 수 있어요. 로그인하면 **소셜 이름 그대로** 쓸지 **직접 정할지** 고를 수 있고(선택은 브라우저에 기억), 같은 계정은 어느 기기에서든 같은 플레이어로 인식돼요.

### 설정

각 제공자 개발자 콘솔에서 OAuth 앱을 만들고 Redirect URI를 등록한 뒤 환경변수를 설정하세요. 환경변수가 없는 제공자는 버튼이 나타나지 않아요.

| 제공자 | 콘솔 | Redirect URI | 환경변수 |
| --- | --- | --- | --- |
| Google | Google Cloud Console → API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID(웹) | `<배포주소>/auth/google/callback` | `GOOGLE_CLIENT_ID` `GOOGLE_CLIENT_SECRET` |
| GitHub | Settings → Developer settings → OAuth Apps | `<배포주소>/auth/github/callback` | `GITHUB_CLIENT_ID` `GITHUB_CLIENT_SECRET` |
| Discord | Developer Portal → Applications → OAuth2 | `<배포주소>/auth/discord/callback` | `DISCORD_CLIENT_ID` `DISCORD_CLIENT_SECRET` |

공통 환경변수:

| 변수 | 설명 |
| --- | --- |
| `SESSION_SECRET` | 세션 쿠키 서명과 계정 ID 생성에 쓰는 비밀값. **운영 필수**이며 길고 무작위인 문자열이어야 해요. 없으면 서버를 재시작할 때마다 모두 로그아웃돼요. `render.yaml`은 자동 생성하도록 해 두었어요. |
| `PUBLIC_URL` | 배포 주소(예: `https://wordlink.onrender.com`). Render에서는 `RENDER_EXTERNAL_URL`을 자동으로 써요. 로컬 테스트는 `http://localhost:3000`을 Redirect URI로 등록하세요. |

### 동작과 보안
- 요청 범위는 공개 프로필(Google `openid profile`, Discord `identify`, GitHub 기본)뿐이고, 이메일은 요청도 저장도 하지 않아요.
- `state` 값을 서명된 쿠키로 검증하고, 세션은 HttpOnly · SameSite=Lax(HTTPS면 Secure) 쿠키(30일)예요.
- 로그인한 연결의 `playerId`는 서버가 `HMAC(SESSION_SECRET, 제공자:계정ID)`로 만들며 클라이언트가 보낸 값은 무시해요. 게스트가 `u-`로 시작하는 ID를 흉내 내거나 남의 자리를 복원할 수 없어요.
- 로그인 세션은 쿠키에만 있고, 전적·경험치는 아래 기록 저장소에 따로 저장돼요.
- 로그아웃은 홈 화면의 `로그아웃` 버튼이에요.

## 계정 기능: 레벨 · 랭킹 · 기록 저장

**소셜 로그인한 계정에만** 기록이 저장돼요. 게스트도 바로 플레이할 수 있지만 경험치와 전적은 쌓이지 않아요. (닉네임만으로는 같은 사람인지 확인할 방법이 없기 때문이에요.)

### 저장되는 것
- 경험치(레벨), 플레이한 판 수 · 우승 · 라운드 승리, 누적 점수, 한 경기 최고 점수
- 낸 단어 수, 가장 긴 단어, 가장 높은 점수를 받은 단어, 미션 글자 성공 횟수, 연승 / 최고 연승
- 최근 10경기(순위 · 점수 · 받은 경험치)
- 마지막으로 쓴 닉네임과 프로필 사진. 이메일 등 개인정보는 저장하지 않아요.

| --- | --- |
| 로비 → **👤 마이페이지** | 레벨 · 칭호 · 경험치 바 · 전적 · 최근 경기 |
| 로비 → **🏆 랭킹** | 누적 경험치 상위 30명, 내 순위 |
| 로비 `내 정보` 패널 | 레벨 · 경험치 바 · 프로필 사진/닉네임 변경 |
| 접속자 목록 · 대기실 · 점수판 · 결과 화면 | 이름 옆 `Lv.N` 배지 (칭호 구간마다 색이 바뀜) |
| 결과 화면 | 이번 경기에서 받은 경험치 · 내역 · 레벨 업 표시 |

### 경험치와 레벨

경기가 끝날 때 한 번 정산해요. (`progress.js`의 `calcMatchXp()`)

| 항목 | 경험치 |
| --- | --- |
| 경기 참가 | +20 |
| 획득 점수 | 점수 × 0.2 (최대 300) |
| 라운드 승리 | 승리당 +10 |
| 최종 우승 | +40 (3인 이상이면 준우승 +15) |
| 인원 보너스 | 3인부터 (인원 수 − 2) × 5 |

- 레벨 L → L+1 에 필요한 경험치는 `100 + 40(L−1) + 4(L−1)²`이에요. (1→2: 100, 10→11: 784, 30→31: 약 3,900) 최고 레벨은 99예요.
- 칭호: 낱말 새싹(1) · 글자 수집가(5) · 단어 탐험가(10) · 말잇기 달인(20) · 어휘 장인(35) · 사전 박사(50) · 언어의 마법사(70) · 말잇기 전설(90). 이름과 구간은 `progress.js`의 `TITLES`에서 바꿀 수 있고, 배지 색 구간은 `client.js`의 `TIER_FROM`을 같게 맞춰 주세요.
- **지급 조건**: 경기 전체에서 단어가 6개 이상, 단어를 낸 사람이 2명 이상이어야 하고, 본인이 단어를 1개 이상 냈으며 중간에 나가지 않았어야 해요. 혼자 방을 만들어 경험치를 얻는 것을 막는 최소한의 장치이고, 계정 여러 개를 쓰는 어뷰징까지는 막지 못해요.

### 기록 저장소 (중요)

| 환경변수 | 저장 위치 |
| --- | --- |
| (없음) | 서버 디스크의 `data/profiles.json` (`DATA_DIR`로 폴더 변경). 바뀐 내용을 2초 모아 저장하고 종료 시에도 저장 |
| `DATABASE_URL` | PostgreSQL의 `wl_profiles` 테이블 (처음 실행 때 자동 생성). `pg` 패키지는 `npm install`이 선택 의존성으로 설치. SSL을 끄려면 `DATABASE_SSL=false` |

> ⚠ **Render 무료 플랜은 재배포·재시작 때 디스크가 초기화**돼요. 파일 저장을 쓰면 그때마다 모든 기록이 사라지니, 배포 서버에서는 외부 PostgreSQL(Neon · Supabase 등)을 만들어 `DATABASE_URL`을 넣거나, 유료 플랜의 영구 디스크에 `DATA_DIR`을 지정하세요. PostgreSQL 연결은 실제 DB로는 아직 시험하지 못했으니, 처음 연결할 때 로그(`Profiles: N loaded`)를 꼭 확인하세요.

기록은 `계정 ID의 SHA-256`으로 구분해요(`auth.js`의 `statsKeyFor`). `SESSION_SECRET`을 바꿔도 기록은 유지되고, 이 키는 서버 밖으로 나가지 않아요.

## 도우미 복구 🐶

화면 구석의 강아지 마스코트 **복구**가 게임 상황에 맞춰 말을 걸어요. 눌러서 도움말을 볼 수도 있어요.

| 기능 | 설명 |
| --- | --- |
| 상황별 반응 | 내 차례(쓸 수 있는 글자 안내) · 미션 성공 · 긴 단어·체인 칭찬 · 5초 이하 경고 · 라운드 시작/종료 · 탈락 위로 · 우승 축하 |
| 오류 풀이 | 단어가 거부되면 이유를 쉬운 말로 설명해요. (사전에 없음 · 이미 사용 · 한방 금지 · 첫 글자 불일치와 두음법칙) 같은 이유는 12초에 한 번만 말해요 |
| 도움말 메뉴 | 기본 규칙 · 두음법칙 · 점수 계산 · 미션 글자 · 라운드와 탈락 · 한방 단어 · 기능 안내. Esc로 닫기 |
| 조절 | `말 줄이기` · `자리 바꾸기`(왼쪽/오른쪽) · `숨기기`(🐾 버튼으로 다시 부르기). 설정은 브라우저에 저장(`wordlink.bokgu.v1`) |

- 내 차례에는 방해하지 않도록 팁을 말하지 않고, 아무 일 없이 오래 두면 졸아요. `prefers-reduced-motion` 설정을 따라요.
- 구성은 `mascot.js`(캐릭터 · 말풍선 · 메뉴 · 반응 로직)와 `mascot.css`예요. `client.js`는 `window.Bokgu?.…` 훅만 호출하므로, 두 파일과 `index.html`의 연결 두 줄을 지우면 복구만 깔끔히 빠져요. 문구는 `mascot.js` 위쪽의 `TOPICS` · `TIPS`에서 고칠 수 있어요.

## Socket.IO 이벤트

비밀번호와 `playerId`는 목록·스냅샷·채팅으로 절대 내보내지 않아요. (`playerId`는 재접속에 쓰는 인증 정보예요.)

### 로비

| 이벤트 | 방향 | 설명 |
| --- | --- | --- |
| `lobby:enter` / `lobby:leave` / `lobby:refresh` | 클라 → 서버 | 로비 입장·퇴장·새로고침. `lobby:enter`는 `avatar` 지원 |
| `lobby:chat` | 양방향 | 채팅 전송 / 새 메시지 수신 |
| `lobby:rooms` / `lobby:users` | 서버 → 클라 | 방·접속자 목록 갱신 (0.3초 단위로 묶어 전송) |

### 방

| 이벤트 | 방향 | 설명 |
| --- | --- | --- |
| `room:create` | 클라 → 서버 | `title`, `password`, `maxPlayers`, `rounds`(1~25), `totalSeconds`, `turnSeconds`, `allowOneShot`, `avatar` |
| `room:join` | 클라 → 서버 | `password`, `avatar` 지원. 실패 코드: `PASSWORD_REQUIRED` · `PASSWORD_WRONG` · `PASSWORD_BLOCKED` · `STARTED` · `FULL` · `KICKED` |
| `room:quick` | 클라 → 서버 | 빠른 입장 |
| `room:settings` | 클라 → 서버 | 방장 전용(대기실). `allowOneShot`(true/false) 등 방 설정 변경 |
| `room:kick` | 클라 → 서버 | 방장 전용(대기실). `targetId`를 내보내고 같은 방 재입장을 막음 |
| `room:kicked` | 서버 → 클라 | 추방된 본인에게만 전송. 클라이언트는 로비로 돌아감 |
| `room:chat` / `room:chatlog` | 양방향 | 방 안 채팅 / 최근 대화 |

### 프로필

| 이벤트 | 방향 | 설명 |
| --- | --- | --- |
| `profile:me` | 클라 → 서버 | 내 프로필 |
| `profile:avatar` | 클라 → 서버 | 프로필 사진 변경 (로비에서) |
| `profile:reward` | 서버 → 클라 | 경기 종료 시 내가 받은 경험치 |
| `ranking:top` | 클라 → 서버 | 랭킹 (1초에 1번) |

## 알려진 제한 사항

- 방과 게임 진행 상태, 로비 접속자·채팅은 서버 메모리에 있어서 서버가 재시작되면 사라져요. 클라이언트는 재연결 시 자동으로 로비에 다시 들어가요.
- 인스턴스를 여러 개 띄우려면 Socket.IO 어댑터와 공유 저장소가 필요해요.
- 관전자 기능은 없어요. 게스트 기록, 업적, 시즌 랭킹도 없어요.
- 시작 단어 추천과 막다른 글자 방지 기능은 아직 없어요.
- 초기 사전은 확장용 기초 데이터예요.
- 공용 서버에 배포하기 전에는 요청 빈도 제한, 관리 도구, 사전 품질 검증, 운영 로그와 모니터링을 추가하는 것이 좋아요.
